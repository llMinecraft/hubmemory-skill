# 日报 v3：低成本分层全天总结

## 目标与边界

AI 只撰写全天总结；统计、会话明细、来源状态、参考文献和最终 Markdown 均由程序生成。不让 AI 重写任务清单、不生成重复 JSON，也不在日报流程额外调用模型抽取 profile。

## 人读结构

```markdown
# YYYY-MM-DD 工作日记
> **TL;DR**: 程序从总结首个有效句提取

## 全天总结
### 今天做了哪些事
- 按工作主线归纳，而不是罗列工具操作。[1]
### 主要结果
- 区分来源声称与已验证事实。[2]
### 待办与阻塞
- 未收束的工作、阻塞条件和下一步。[3]
### 参考来源
- [1] 程序填写完整会话、事件和来源位置

## 数据统计（程序生成）
## 工作事项（程序生成）
## 会话明细（程序生成）
```

正文避免文件路径、代码、命令、模型提示词和大段原始输出。AI 仅引用证据包已有的 `[n]` 编号，不生成来源路径或 ID。程序只列出正文实际使用的引用；需要核验时再点开，而非每次加载完整事实流。

## 使用入口

领取日报租约后运行：

```bash
python3 scripts/daily_report.py --date YYYY-MM-DD --pack
# 或等价的只读入口
python3 scripts/daily_input.py --date YYYY-MM-DD
```

将返回的编号证据交给当前模型；只保存 `## 全天总结` 及三个子节为候选。随后使用领取时的 session/token 调用 `report_due.py publish --kind daily --input <候选文件>`，程序生成引用表与其余部分。不要再用直接改写终稿后 `complete` 的方式完成新日报。

## 数据与兼容

- 保留唯一事实源 sessions.jsonl、程序派生 evidence.jsonl。
- 新日报移除末尾 Agent-readable summary JSON，不生成相同内容的 JSON 旁车。
- MANIFEST 使用现有证据；hub day 默认只读 TL;DR 与全天总结，完整明细按需读取。
- 历史 v2 日报读取兼容，不因格式版本自动重写旧报告或丢掉旧引用。
- 月报是独立契约，本次不擅自扩大为重写全部月报格式。
- 租约、来源快照、输出哈希、归档/发布共用锁保持有效；简化内容不等于取消安全校验。

## 成本控制

程序提供编号、裁剪过的证据包：优先各会话首个目标和最新结果，再均衡补充；每 agent 最多 40 条、全局最多 80 条，并限制约 32K 渲染字符单位（不是严格 UTF-8 字节数），明确显示覆盖范围。模型一次只输出总结；程序不请求模型生成统计、任务明细、索引、TL;DR 或引用表。节省的是模型输入/输出和跨会话重复读取，不能把缺失 tokens_out 当作已测量的真实节省比例。
