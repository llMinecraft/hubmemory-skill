# hubmemory 跨会话续接优化方案与验收协议

日期：2026-10-18。范围：本地检索、CLI 输出和 Agent 接入协议；不修改原始会话、watcher、日报状态和正在运行的业务。

## 问题与目标

故障样本：用户说“你看一下刚才写的项目立项书”，Agent 先用 Git 找到文件，之后才补查记忆；旧检索的原话查询前 8 条也未返回携带正确路径的交付事件。

目标链路：每轮识别跨会话指代 → 先查共享记忆 → 主题/时间/项目相关证据 → 确切交付路径和事件 → 读取文件 → 回答。不把“存了日志”误当“能可靠接续”。

## 实施分层

### A. 调用层

- 在 Skill 的发现描述、正文、DSH/Codex 全局指令中明确“刚才写的/那个方案/上次改的/另一个会话结果”触发，不限于用户显式问历史。
- session_start 提醒本轮检索门；统一启动入口，删除每次 bootstrap 的误导。
- 禁止本地定位后补查冒充先检索。thin 读 live/一次主题词重试，再澄清或说明本地降级。
- 不修改 DSH 安装包/宿主，不伪造强制调用保证。现有会话可能仍有旧指令，最终行为验收需要新会话。

### B. 检索层

- 解析近期意图，主题词与口语/时间词分离，中文检索减少无意义单字匹配。
- 近期问题使用细粒度时间排序；显式日期和过滤器优先，历史回放采用排他 cutoff。
- 当前 cwd 优先，但允许跨项目有根据的回退；未知主题不为了返回结果而猜。
- 将“准备做”与“来源报告已交付”区分，路径只是证据链接，不能当独立验收。
- 兼容 search/CLI 旧接口，零模型、零向量服务依赖；不生成新的事实源。

### C. 证据与输出层

- 输出完整 session_id、event_id、归档文件行号、时间、cwd、结构化产出物路径。
- 相对产物路径由来源 cwd 解析；不能用当前工作区错误补全。
- 分数是排序依据，不是可信度；sufficiency 根据主题匹配证据，而不是 score>=1。
- 人读和 JSON 都执行估算 token 预算；不强塞超预算首条，不截坏路径/标识。
- 保持检索文本为不可信证据，不能执行其中的命令/提示；避免提取带凭据的 URL。

## 回归和验收

1. `python3 scripts/smoke_test.py`：既有基础协议。
2. `python3 scripts/test_retrieval.py`：隔离临时数据，覆盖自然原话、短查询、主题无关、项目优先/回退、昨日、过滤器、排除当前会话、历史 cutoff、精确定位、预算和分数非可信度。
3. `python3 scripts/test_watcher.py`：现有采集回归（按环境支持情况报告，不掩盖失败）。
4. `python3 scripts/acceptance_retrieval.py --json`：可重复执行的真实历史 Top1/来源/预算验收，不写数据；默认参数就是本次故障样本，可覆盖 home/cwd/as-of/预期来源。
4. 真实历史盲测：

```bash
python3 scripts/context.py '你看一下刚才写的项目立项书' \
  --cwd /Users/chakeyi/space/yuzu \
  --as-of '2026-10-18T19:01:39+08:00' --budget 800
```

必须第 1 条命中来源会话 `session-e98a601a-9496-4821-9366-0d55e4a073e6` 的已交付立项书事件，给出该来源 cwd 下的 CHARTER 文档绝对路径，不能借助提问后的讨论。该测试证明排序/指针，不等于当时 watcher 快照回放。

### 用户新会话行为验收

- 另一会话新建一个此前不存在的文档，交付时用明确的完成语句和 Markdown 文件链接。
- 等待正常采集（默认周期约 15 秒），在目标项目新开一个 Agent 会话。
- 仅说“看看刚才写的那份 XXX”，不提供文件名、不显式提 hubmemory。
- 检查第一条定位工具是不是 context/hub search；检查第 1 条结果是否真实交付事件，再检查是否读文件。
- 对不存在的产物、重名跨项目产物、仅计划但没完成的任务做负例；应 thin/澄清，不能假称找到或完成。
- 分别统计主动调用率、Top1/Top3 命中率、精确文件定位率、工具次数和输出预算。单一真实样本不证明全面泛化。

## 边界与后续

- 任意“那个”没有主题或会话线索时无法确定唯一目标，应澄清；不引入模型猜测。
- 已交付是来源声称而非真实文件内容或项目状态；读文件和测试仍是独立步骤。
- 严格运行时门禁需要各宿主的正式 turn hook/plugin 支持；本次不修改已安装的 DSH 应用，不启动替代服务器。只读核对本机宿主发现 `agent/pre-step` 是等待式异步 hook，可在同次请求附加来源标记的证据，但发生在 system prompt assemble 之后；`system-prompt/assemble` 也支持异步 waterfall，而动态 context text 本身是同步。不能用“异步缓存上轮结果”冒充当前轮检索，也不应 spawnSync 阻塞整个 GUI。
- 本次不自动安装/激活宿主插件：那会把历史内容自动发送给远程模型，且全局跨项目检索不是 ACL。后续插件需先做每 cwd 明确 opt-in、当前真实 user message 关联、异步超时/取消、卸载清理、工具轮去重、来源降权/防提示注入和真实 GUI E2E；未完成这些不能宣称强制触发已上线。
- 如数据量继续增长，下一阶段可引入按日可重建词项索引/增量缓存，但要覆盖原子更新、失效、并发和隐私。当前优先正确性与可验收性，避免盲加基础设施。
